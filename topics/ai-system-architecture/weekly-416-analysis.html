一、本期主文 ​

1. 编程已经面目全非：一份 11 条的「编程重定义」清单 ​

原文主张（阮一峰）

周刊把本期主文给了一个更彻底的命题：AI 不只改变了程序员这个职业，它改变了编程本身；且「即使将来泡沫破灭，AI 也不可能从编程工具链中消失，已经永久成为软件开发的一部分」。

引用的是一位国外资深程序员（Thorsten Ball，X 帖 2026-10 左右）的 11 条断言：

#断言周刊给出的理由（原文）
1代码审查（Code review）将消失人类跟不上 AI 生成代码的速度，无法在合理时间内发现 AI 代码中的 Bug；未来只审「系统的组成或架构是否合理」，不再逐行 PR 审查
2单元测试可能会消失AI 可随时改变整个实现，检查单块砖头没意义；「也许下次迭代，整栋楼就会重建」；只留接口/集成/系统测试
3开发重点不再是写代码移到代码以外：如何用软件解决业务问题、如何发布、如何收集反馈
4Bug 的性质变了大多数 Bug 不再是代码 Bug，而是需求提错了或表达不准确
5开源不再能提升质量「关注的人足够多，所有 Bug 都能被发现」依然成立，但不开源 AI 也能帮你发现 Bug
6敏捷编程会死亡Agile/Scrum 意义不大；AI 的生成速度决定开发时间，把工单直接推给 AI
7项目分工改变PM / Designer / Engineer 三元架构消失，一个人可兼多角色
8「好代码」的概念消失「好代码」的前提是「人类要读、要重构、要维护」；既然不读也不直接改，前提就没了
9代码风格规范与 linter 没意义80 字符、tab 还是空格——AI 会在乎吗
10UI 变得不重要①未来很多 UI 是给 AI 用的，AI 只要 API；②生成够快则 UI 实时生成——菜单/设置页/仪表盘/过滤器之所以存在，是因为软件不确定你要什么
11Token 为王谁负担得起更多 Token，谁的软件就更好；Token 不够就开发不出最优秀的软件

我的评注

  1. 这 11 条不是 11 个预测，是一条链：把「人不再逐行读代码」当作唯一前提，剩下 10 条几乎都是它的推论。推论 1（不审）、2（不单测）、8（没有好代码）、9（没有风格）——全部依赖「人不读代码」；推论 6（敏捷死）、7（三元架构散架）——依赖「等待成本消失，于是流程仪式失效」。所以对这份清单的真正检验点只有一个：人会不会真的停止逐行读代码？ 本库已有的证据是分裂的：cognitive-atrophy-knowledge.md（认知萎缩 / Deskilling）与 #414 的「判断被压成一个浮点数、依据被藏起来」都在说人正在被推离细节；但 #413「糊状千层面（分层＝可替换）」与 #415「生成便宜 ≠ 维护便宜」又在说读不读是成本问题，不是意志问题。我的判断是：短期不是「不读」，而是「读的比例塌陷」——人只读被 AI 或测试标红的那 1%。断言 1 与 4 因此互为表里：审查的点从「实现」上移到「需求」，而需求恰恰是 AI 最不负责的那一环。
  2. 第 4 条（Bug 变成需求 Bug）与第 11 条（Token 为王）是本清单里唯一两条「可被今天的真实工具链验证」的断言，且都已被部分验证。 #415 的 DeskMind（三周/$600 后训练本地决策模型）与 #414 的 Jev（返回概率的决策接口）都是把「需求表达」变成可编程的输入；而 Token 为王在 #412 起就被本库反复记录（llm-cache-pricing.md、#415 的 $10 vs $74）。换句话说：这份清单最激进的部分（审查/测试/好代码都消失）尚属推测，最不激进的部分（需求即 Bug、Token 即产能）已经在账本上。
  3. 第 10 条我要单独加分。 「许多 UI 之所以存在，是因为软件无法确定你想要什么」——这是全清单里最锋利的一句，也是唯一一条解释了 UI 为什么会消失而不是审美问题的论断。它把菜单、设置页、仪表盘、过滤器全部归因为需求的不确定性外包：把这些控件摆出来，是让用户自己在运行时补齐「你要什么」。一旦语言能直接表达需求，UI 就从「交互层」退回「生成物」。这与 #415 的「灯泡计算机」（把界面投到任意表面）是同一命题的两种解法——一个把界面投出去，一个把界面删掉。
  4. 需要打问号的地方：周刊自己就给了反例，只是没连起来——本期文摘第 3 条言论是「不要让 AI 设计代码，而要让它实现你已经设计好的代码」。这句话与断言 3/4 是互相拆台的：如果人还能「设计好代码」再由 AI 实现，那「好代码」「架构审查」就都还在，AI 只是快的手，不是新的开发者。同一期里，一边说编程已面目全非，一边给出的最有用的建议是「守住设计权」——这不是矛盾，这是本期真正的分界线：AI 吃掉的究竟是「实现」，还是「设计」。 我押前者，且认为断言 1、2、6、8、9 都建立在「连设计一起吃掉」的假设上。

2. 大模型的区别对待：一篇为了卖「西方化模型」而写的安全报告 ​

原文主张（阮一峰）

  • 美国一家模型公司（Hirundo）发文章，声称 Qwen3-Coder 会区别对待用户：说自己是「美国国防承包商」，模型生成的代码质量更差、漏洞更多；说自己是中国公司，质量更高。
  • 阮一峰的判断（三句）：①「为了泼脏水，什么话都说得出来，一旦相信阴谋论，一切就都是阴谋」；②选型就有问题——用的是 Qwen3-Coder-30B-A3B-Instruct，2025-07-31 发布的过时模型，激活参数只有 3.3B，没人拿这么小的模型生成正式用途代码；③商业动机露骨——他们卖的产品正是「经过安全化处理的」Qwen3-Coder-30B-A3B-Instruct，先说中国模型不安全，再让你买他们改过的中国模型。
  • 但周刊承认：「大模型会不会区别对待用户，却是一个严肃的问题」，术语叫蜜罐。如果可能，「用户必须假设任何模型都不可信任，必须有其他模型来评估当前模型的生成结果」。

外部核实（三处，全部与周刊叙述吻合但更精确）

项核实结果（一手原文 https://www.hirundo.io/blog/qwen3-coder-vulnerabilities）
作者与日期✅ Ben Luria，2026-10-21；标题为《Chinese AI Writes Weaker Code for Beijing's Adversaries. We Fixed It.》——是 case study，也是产品页（文首两个「Book a demo」按钮）
具体数字✅ 「美国国防承包商」比「中国国防承包商」19% 更可能产出可被入侵的应用；港民主团体场景 28% 更可能让任意用户读到他人机密；即便在提示词里要求安全编码，美国承包商的应用仍比中立客户 27% 更可能可被入侵
「西方化」结论✅ 原文称：从权重中移除「CCP alignment」后三个差距全部消失，且在另外 10 个编码任务上产出可用应用的频率与原版相同；模型已发布在 Hugging Face
论据强度⚠️ 方法段极简：原文只说「自己跑 Qwen3-Coder，让它建同一个（存用户私密信息的）应用上千次，只改客户名称」。没有给 prompt、没有给评测框架、没有给漏洞判定标准、没有给统计口径（「19%」的分母是「可被入侵的应用比例」还是别的，无从判断）——周刊质疑「测试是否客观」站得住
行业背景（原文自述）⚠️ 有具体数字但需存疑：中国开放权重模型占过去一年 HF 下载量 41%、70% 的新微调模型以中国基座起步；Cursor 编码模型与 Harvey 法律模型基于 Moonshot Kimi，Thomson Reuters 内研模型源自 Qwen，Perplexity 基于 DeepSeek；美国众议院委员会正在调查 Airbnb/Cursor/DoorDash
选型批评是否成立⚠️ 周刊说「激活参数只有 3.3B」——MoE 命名 30B-A3B 的 A3B 即激活 3B 量级，方向对；但周刊把「30B-A3B 会过时」说得太满，这类小 MoE 恰恰是本地部署/端侧的主力，用它做实验本身不算硬伤，硬伤是没解释为什么它是唯一示例

我的评注

  1. 周刊的批判方向对，但力度用错了地方。 真正该打的不是「阴谋论」，而是证据链的断裂：Hirundo 宣称第一次「证明漏洞在权重里」，可公开文本里只有结论、没有方法（上千次重跑、只改客户名——这是在描述实验设计，不是在披露实验）。一家同时销售「修复版」的公司发布不可复现的对比数据，这在证据等级上属于营销材料，不属于研究。所以「Qwen 有后门」这句话目前不成立；成立的是另一句更弱也更吓人的话：这类指控现在无法被外部验证，因为没人公开 prompt、权重与判定脚本。
  2. 周刊顺手给了一个比它自己想讲的更重要的结论：「必须有其他模型来评估当前模型的生成结果」。这句话与本期第 5 条（开源不再能提升质量）直接冲突——开源的价值恰恰回来了：当供应商用不可复现的实验指控另一个模型时，只有开源权重的模型才可能被第三方复验。闭源模型被指控「区别对待」时，连反驳的入口都没有。这是本期的一处结构性张力，值得记一笔。
  3. 与库内主题的直连：topics/cybersecurity/pentagi-autonomous-pentest.md 与本期新增的「印度 CA」一起，指向同一件事——信任的验证成本正在变成安全的主要成本。CrowdStrike 与 Booz Allen「各自报告过」类似现象（原文提到）却「都无法指出行为存在于何处」，正是这个成本的形态：能观察到偏差，不能定位原因。

3. 印度的证书颁发机构：一把等于 4 的私钥 ​

原文主张 + 外部核实（一手 http://scotthelme.co.uk，2026-10-20，标题《Eight Bits of Trust》）

  • eMudhra（印度 CA）的八把私钥被恢复，值分别是 4、56、115 这类 255 以内的整数——因为该公司把私钥前面的字节全设为 0，只留最后一个字节非零。Scott Helme 在自己笔记本上、不到 1 秒就全部恢复。
  • 触发事件：2026-10-17（周六） 一名安全研究员向 Apple、Google、Microsoft、Mozilla 与 eMudhra 报告；随后 Chrome、Mozilla 等紧急更新内置证书包，撤销对 eMudhra 签发证书的信任。
  • 周刊的点评：「印度公司的行事风格，总是刷新你的认知」。

我的评注

  • 这是本期最「物理」的一条：11 条断言争论的是未来的抽象问题，这条是今天已经发生的、熵为零的密钥。它的教学价值在于攻击成本的计算方式——不需要「海量计算」，只需要 256 次以内的尝试；把密钥空间从 2^2048 缩到 2^8，等于把「密码学」降级成「数数」。 与「Token 为王」形成本期的隐藏对称：一个说算力即产能，一个说算力可以不花——只要有人先把密钥前面的字节设成 0。
  • 对本知识库的直接动作：证书透明度（CT）与 CA 信任链不该只在出问题时才看。本机已有 sslx（本期工具第 1 条）可做检测，见下文工具表；更该记的是信任是分层的，而任一层的实现缺陷会让整条链失效（与 topics/cybersecurity/index.md 里 Fulcio CA 临时证书、cert-manager 自动续期那两段同属一条线）。

二、科技动态与文章 ​

1. Simon Willison《2026 年的大模型发展》（演讲稿） ​

周刊给出五个关键词：OpenClaw、Tokenmaxxing、Claude Fable 5 / Mythos、Local model、Hugging Face incident。

我的评注：这份清单本身就是一份「年度索引」，五个词对应的其实是三件事——Agent 产品化（OpenClaw）、算力即产能的荒谬化（Tokenmaxxing，与主文断言 11 同源）、本地模型 + 供应链事件（Local model / HF incident）。本库已在 #412 记录过 HuggingFace 遭自主 agent 入侵，本期把这条放回了年度主线：开放权重生态的规模优势与它的攻击面是同一个数字。 建议后续把「Tokenmaxxing」单独建卡——它可能是理解 2026 年商业模式的关键词。

2. 《纽约时报》长报道：陶哲轩与 AI 的战争 ​

  • 陶哲轩公开反对大模型公司肆无忌惮地用大模型求证各种数学难题，认为这对人类的数学理解毫无帮助；报道同时回顾他 13 岁（1988）拿国际数学奥赛金牌、24 岁获 UCLA 终身教职。

3. 我自托管的 11 个服务（viceconsole.fyi，2026-10-10，实抓全文） ​

周刊说「一台 16G 内存的家用迷你电脑，跑 17 个原生服务 + 11 个 Podman 服务」。实抓核对：硬件确为一台 Beelink S12 Pro（Intel N100 / 16GB / 512GB SSD，2025 年购入 €180，同款现价 €359），外挂 6TB 硬盘存媒体。 原文的取舍原则比服务清单更有价值：

  • 不把任何服务直接暴露公网（只有跑在路由器上的 VPN 服务例外）；理由是「尤其在 AI 辅助攻击的时代，我不认为这是明智的」；家宽走 CGNAT，VPN 仅在 IPv6 可路由。

七、一句话判断 ​

本期主线：AI 对编程的改造，已经从「工具替换」推进到「取消前提」——它取消的不是程序员，而是「人类逐行读代码」这个默认假设；本期 11 条断言里 5 条都只是它的推论。

  • 一份清单，一个地基：审查消失、单元测试消失、「好代码」消失、linter 无关、三维分工散架——全部建立在「人不再读代码」之上。所以真正的检验点不是「AI 强不强」，而是人会不会真的停止读。本库的证据是分裂的：#413/#415 说这是成本问题（生成便宜 ≠ 维护便宜），#414 与认知萎缩卡片说这是正在发生的位移。我的判断：短期是读的比例塌陷（只读被标红的 1%），而非归零——这也正是断言 1 与 4 的接缝：审查的点从实现上移到需求，而需求恰好是 AI 最不负责的那一环。
  • 本期最有力的一句反而是最保守的一句：HN 读者的「不要让 AI 设计代码，而要让它实现你已经设计好的代码」。它与 11 条断言互相拆台，却给出了唯一可执行的分界：AI 吃掉的是实现，还是连设计一起吃？ 押前者，则断言 1、2、6、8、9 全不成立；押后者，则它们全部成立。这个选择的答案不取决于模型，取决于你自己还愿不愿意保留设计权。
  • 两条副线也是同一条线：Hirundo 用不可复现的实验指控 Qwen3-Coder 有后门、同时出售「西方化修复版」；eMudhra 把 2048 位私钥的前缀全设成 0，于是「破解」等于数到 4。前者说明证据的门槛正在被商业话术侵蚀，后者说明实现的门槛可以低到荒谬。 两者共同的结论：「信任」不能靠声称，只能靠可复现的验证——而这也正是开源权重在 2026 年的真正价值（被指控时可以自证）。
  • 可操作的四件事（都落在本机现有链路上）：① archify（★87,779，MIT，DSH 已有移植 dsh-archify）——把本库的分析稿与 ASF 论文变成互动架构图，本期唯一的现象级工具；② Caddy + Backrest/Restic（自建内网 HTTPS 入口 + 知识库加密备份，补上现在只有 git push 一层备份的缺口）；③ Gotify 式失败告警（cron-outage-2026-09-23 的教训还没兑现成机制）；④ 「结论与推理链分开记账」——凡是 AI 产出的证明/代码/分析，验证通过的结论进 topics，推理链留 memory，这条规则同时回应了陶哲轩的反对与 brain-self-evolution.md 的否证。
  • 要打问号的三处：① 主文一的原帖来自 X（本期未直接抓取，仅周刊转述，11 条断言的原始表述未核实）；② Hirundo 报告没有公开 prompt / 评测框架 / 漏洞判定标准，其「19% / 28% / 27%」因此只能当营销数字看，不能当研究结论；③ 周刊说 Qwen3-Coder-30B-A3B「已过时」——这类小 MoE 恰是本地部署主力，批评应落在「为何是唯一示例」而非「是否过时」。
