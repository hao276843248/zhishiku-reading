  • 科学日报 2026-10-29（AI 系统架构） — 第48期 AI（5 篇 arXiv）：ThinkWorld：把动作思维写成动力学链（CoD）（一串离散运动 token，刻画连接当前世界与未来状态的中间动力学，作为跨本体共享动作表示），先由带动作标注演示初始化，再预测每个 CoD 诱导的未来、强化预测更贴合观测的 CoD → 无动作标注视频也能提供监督，人/机经验在同一推理空间互炼，实现人→机迁移与强泛化（arXiv:2610.37666）/ Attention as Lattice Gauge Theory：证明在逐实体规范自由下，不共享环的关系无法相互作用、三角形的唯一规范不变分数是和乐 H=T_ijT_jkT_ki 的类函数（Wilson 环）、边的唯一等变更新是 U=Ψ(H)T_ij → Wilson 环边注意力是唯一解，不是设计选择之一；holonomy attention 零训练在 1/5 边污染稀疏图上推断 S₄ 关系 0.88（交换架构上限 0.083）、污染三角标记 AUC 0.99、可无标签聚类（arXiv:2610.37656）/ 工具使用智能体缩放律：SynthAPI 沿工具/任务/数据库三轴显式控制环境多样性，849 模型 × 458,752 任务推出可预测下游泛化的缩放律——扩展工具与数据库多样性比增加任务数更有效、提高数据复杂度收益更大，按此缩放超既往工作（arXiv:2610.37648）/ Heads of Security：可学习逐头注意力门强制指令—数据分离——黑盒 RL-Hammer 对 GPT-OSS-20B ASR 97%、SecAlign 85%，对 HoS 仅 10%；白盒 Claudini 攻 HoS 需 3 倍 FLOPs；few-shot 不损基座效用（SecAlign/ASIDE 会退化）→ 把安全做进注意力分配而非权重、结构分层 > 事后过滤（arXiv:2610.37657）/ 无标签 RLVR 崩塌的集体动力学：问题共享参数时，只要单问题自强化漂移的群体平均斜率 ⟨F'⟩>0 即放大共享扰动——锐化被 1/N 拖慢，共享模 ∝λ² 与 N 无关，临界问题数 N_c≈ln(1/δ)/(λ²G)；模拟验证尖锐相变、λ²NG 临界放大、初始自信则不崩；小 Transformer 中去掉共享方向完全避免崩塌 → 崩塌是集体动力学问题不是训练 bug；删共享耦合方向即可拆解（arXiv:2610.37553）
  • 科学日报 2026-10-28（AI 系统架构） — 第47期 AI（5 篇 arXiv）：DecisionRAG：免检索器（retriever-free）——用决策模型一次前向对候选分支联合打分、不生成 token，共享上下文使相关性估计可比，像逛图书馆一样从主题逐层下探到段落；无任务训练/无一阶段检索器，MultiDoc2Dial R@1 +13.8、NQ Hit@1 +17.4，268 万段语料每查询 0.7–1.8 秒 → 把扁平检索重构成层级决策 + 同参照系联合评分（arXiv:2610.35868）/ Free to Look, Free to Reason：在 RCAtlas（8 数据集 90 案例）上，三种不规定任何模型调用的简单脚手架（证据包一次调用/SQL/Codex）比五套手工编排的已发表 RCA 智能体更准——简单脚手架 PR@1 65–77% vs 已发表 16–53% vs 非 LLM 6–39%；已发表智能体把十分之一到全部的调用写死、跳过决定性证据；更强模型提升可靠性、多轮脚手架提升能力、推理强度最多改几个点却把耗时放大 7 倍、帕累托最优全出自简单脚手架 → 把工具交给模型 > 替它写好流程；加算力先证明有边际收益（arXiv:2610.35767）/ Audit Where Hacks Pay：GRPO 里强验证器预算怎么花——把「审计哪些弱通过 rollout」与「被抓者奖励」分开；低通过预算审计 LB（先审弱通过最少者）给作弊留的优势质量最小；冻结面板的符号预测 39 次中 33 次（预注册 16 中 13）；LeetCode/Countdown-Code 上 LB 把作弊压到近零，同预算随机审计做不到；期望等价的无偏修正结果差 6.1–11.8 / 8.0–11.5 点 → 把稀缺可信度用在刀刃上（分配>力度）；估计量方差也改变训练（arXiv:2610.35716）/ Profiling a Frontier Agent with EBench：GPT-6-Astra 在 EBench 上与后训练 VLA/WAM 同观测协议对比——直接控制短时程领先、泛化波动最小，但长时程/桌面/高精度接触任务落后；带策略的脚手架（可调用后训练策略）互补两者、成功率追平最强对比策略且大幅降 token，但仍低于组件上界（调用次优/缺子目标/接管时打断）→ 能力边界是分维度的表；异构能力分治 > 单模型通吃；组合瓶颈在接口与交接（arXiv:2610.35832）/ EvoRouter：洞察引导的 on-policy 蒸馏驱动自演化多智能体路由——专家把配置轨迹综合成可复用条件路由洞察，特权教师回灌稠密 token 级监督 + 成本感知 RL；19 域内数据集 + 2 域外基准上平均 68.69%、比最强基线 +7.23 点、算力 −50.95% → 经验蒸馏两层结构：先把轨迹综合成可复用洞察再回灌；自演化闭环（arXiv:2610.35690）
  • 科学日报 2026-10-27（AI 系统架构） — 第46期 AI（5 篇 arXiv，数值已回对官方摘要核验）：HarnessMM：受护决定复用（guarded decision reuse）+ 递归自我改进（RSI），把确切动作/字面参数/因果依赖/公开守卫存进可执行决定图（EDG），actor 权重固定下用控制器复用已解析决定替代后续推理回调（Guarded Decision Reuse + Certified Callback Substitution）→ HumanEval 保 Codex 90.82%、Tokens/task 66.72k→47.02k 省 29.54%；DeepSeek Harness 71.43%→85.71%、96.28k→11.62k 省 87.93%；MBPP 消融比 single-use 图省 26.91%、比 retained callbacks 省 19.52% → 把「每次重生算一遍」改成「记住一个受守卫的决定」（arXiv:2610.32813）/ On-Policy Self-Training（OPST）：把 on-policy 自蒸馏重构成自训练框架，由自生成问答对 + 特权推理示范驱动，只给粗粒度主题描述、无人工题面/答案，跨领域提升同时保留未自训练域能力（文本 + 多模态、语言基准 + VQA）→ 自提升的瓶颈是『自产监督里有没有可定位信号』（arXiv:2610.32770）/ 单纯形约束表征：嵌入域从单位球面 S^{d-1} 换成概率单纯形 Δ^{d-1}（非负、单位质量 = 跨模态标定）+ 轻量 softmax 适配器 + 全变差相似度，五基准质心 ℓ₂ 鸿沟降 97%–99%、检索匹配/超无约束模型 → 『对齐问题』常可重写成『几何约束问题』（零训练）（arXiv:2610.32890）/ TopKLoRA：按设计可解释的 LoRA（每 token 只激活 k 个最大适配器潜变量）、纯下游损失训练学出功能因果潜变量，在 sleeper-agent 后门案例（gemma-2-2b、Qwen2.5-1.5B/7B）定位并消融必要且充分电路，稀疏电路比稠密 LoRA 小至多一个数量级、手术式消融不牺牲指令跟随 → 可解释性内建于设计（arXiv:2610.32866）/ 企业级 RAG 知识层：七智能体重工程流水线把 18 服务 241 仓库转成数千工件；扁平向量检索失败（把另一服务的同款规则高分返回、无出错信号），改为本体放到工件层——自描述目录 + 稀疏元数据注册表 + 工件级导航超图，查询先解析到工件 ID 再约束向量搜索 → 歧义是结构性的而非统计性的，一周建成、支撑 100+ 生产缺陷根因、归因 35 个发布回归失败（arXiv:2610.32851）

1. ReAct（推荐入门） ​

是什么：ReAct = Reasoning + Acting，让大模型边想边做

核心思想：

Thought（我想做什么）
→ Action（执行什么工具）
→ Observation（观察结果）
→ ... 循环直到完成

适用人群：刚入门，想快速验证想法

学习成本：1-2周

示例场景：

  • 简单问答+工具调用
  • 单Agent自动化任务
  • 快速原型验证

代码示例：

python
from langchain.agents import AgentExecutor, create_react_agent
from langchain_openai import ChatOpenAI
from langchain import tool

@tool
def search_code(query: str) -> str:
    """搜索代码示例"""
    return f"搜索结果: {query}"

llm = ChatOpenAI(model="gpt-4")
agent = create_react_agent(llm, [search_code])
executor = AgentExecutor(agent=agent, tools=[search_code])
result = executor.invoke({"input": "帮我找Python排序代码"})

2. CrewAI（推荐进阶） ​

是什么：多Agent协作框架，定义角色和任务，让多个AI Agent组队工作

核心概念：

Crew（团队）= Agents（角色）+ Tasks（任务）+ Process（流程）

示例团队：
- 研究员Agent：负责搜集资料
- 分析师Agent：负责分析整理
- 作家Agent：负责输出报告

适用人群：需要多角色协作，已入门ReAct

学习成本：约1个月

示例场景：

  • 市场研究报告自动生成（研究+分析+写作）
  • 代码审查（审查员+测试员+重构师）
  • 客服系统（理解+检索+回复）

代码示例：

python
from crewai import Agent, Task, Crew, Process

researcher = Agent(
    role="行业研究员",
    goal="搜集并整理{topic}的行业数据",
    backstory="你是一名专业的行业分析师",
    verbose=True
)

writer = Agent(
    role="报告撰写员",
    goal="基于研究数据撰写完整的行业报告",
    backstory="你是一名资深商业报告作家",
    verbose=True
)

crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, writing_task],
    process=Process.sequential
)

result = crew.kickoff(inputs={"topic": "新能源汽车热管理"})

3. LangGraph（推荐生产级） ​

是什么：用图结构构建Agent，支持循环、条件分支、长期记忆

核心优势：

  • 支持复杂状态机（有环的图，ReAct/CrewAI是链式）
  • 内置长期记忆和对话历史管理
  • 适合需要多轮交互、复杂决策链的生产系统
  • 微软、AWS等企业级首选

适用人群：有Python基础，需要做生产级系统

学习成本：持续学习（最复杂）

关键概念：

概念说明
State在节点间传递的共享状态
Node每个处理步骤（可以是函数或Agent）
Edge节点之间的连接
Conditional Edge根据State动态决定下一步
checkpoint中间状态保存，支持回滚

代码示例：

python
from langgraph.graph import StateGraph, END
from typing import TypedDict

class AgentState(TypedDict):
    messages: list
    next_action: str

def research_node(state):
    # 搜索信息
    return {"messages": [...], "next_action": "analyze"}

def analyze_node(state):
    # 分析
    return {"messages": [...], "next_action": "write"}

def should_continue(state):
    return "write" if state["next_action"] else END

graph = StateGraph(AgentState)
graph.add_node("research", research_node)
graph.add_node("analyze", analyze_node)
graph.add_node("write", write_node)

graph.add_conditional_edges("research", should_continue)
graph.add_edge("analyze", "research")  # 可能循环
graph.add_edge("write", END)

app = graph.compile()

4. Smolagents（轻量级） ​

是什么：Hugging Face 推出的轻量级Agent框架，极简设计

特点：

  • 代码即Agent，不需要JSON格式定义
  • 支持本地模型
  • 极其轻量，适合嵌入式场景

适用人群：想用本地模型，或构建小型嵌入式Agent

学习成本：1周

三、MoE（混合专家）模型 ​

为什么重要 ​

维度单模型（稠密）MoE（稀疏）
参数量全量激活只激活部分专家
推理成本高低（与效果不成正比）
训练成本高相对低
典型模型GPT-4Mixtral, DBRX, Qwen-MoE

Top 10 开源模型几乎全部采用 MoE 架构

核心原理 ​

输入 Token → 路由网络（Router）→ 选择Top-K专家 → 专家输出 → 加权求和

例如：8个专家，每次只激活2个
→ 推理成本降低 75%，效果几乎不降

四、RAG 3.0 ​

演进路线 ​

版本核心局限
RAG 1.0检索+生成，简单拼凑上下文短，检索不准
RAG 2.0优化检索（向量+关键词混合）多文档整合差
RAG 3.0多Agent架构：路由器+检索+生成当前前沿

RAG 3.0 架构 ​

用户Query
    ↓
【路由器Agent】→ 判断意图，决定用哪些工具
    ↓
【检索Agent】→ 向量检索 + 关键词检索 + 知识图谱
    ↓
【生成Agent】→ 综合检索结果，生成答案
    ↓
【校验Agent】→ 检查幻觉，反馈修正（可选）
    ↓
最终答案
