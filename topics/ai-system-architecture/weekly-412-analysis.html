来源：阮一峰《科技爱好者周刊》第 412 期（封面：上海前滩太古里"英雄联盟 15 周年"展览） 原文链接：https://github.com/ruanyf/weekly/blob/master/docs/issue-412.md 直链：https://raw.githubusercontent.com/ruanyf/weekly/master/docs/issue-412.md 抓取校验：2026-09-16 抓取成功，正文 342 行 / 17,246 字节，含标题「科技爱好者周刊（第 412 期）」✅ 外部核实：Anthropic 官方文章《Formalizing Fermat's Last Theorem》+ GitHub API（仓库 anthropics/fermats-last-theorem）、HuggingFace 官方博客《State of Open Models: Summer 2026》、stitcher.io《No more issues》、jordanlord.co.uk《3 constraints before I build anything》——核实结论均在对应小节标注 状态：已落盘 · 周刊监控首次运行（状态文件此前不存在，本期为基线期）

一、本期主文 ​

1. 禁止 issue，只用 PR ​

原文主张（阮一峰）

Laravel 宣布新规：禁止提交 issue，只能提交 PR。表面荒谬（用户不懂源码怎么报 bug），但他认为合理、甚至值得推广，给了四条理由：

  1. 没有垃圾 issue —— 愿意花时间创建一个 PR，说明他对这个问题更上心；机器人和骚扰者只会提垃圾 issue。
  2. 对维护者更方便 —— 从 PR 得到的信息远多于 issue，更利于理解解决问题，投入时间更少。
  3. 没有增加用户提交难度 —— 不懂源码也能写 PR：向 AI 描述问题，让 AI 生成 PR。"AI 时代，提交 PR 几乎和提交 issue 一样简单。"
  4. 根本原因是资源不足 —— 开源项目应付不了激增的 issue。AI 时代不该鼓励用户把问题抛出来指望别人解决，而应鼓励大家一起贡献。

外部核实（边界修正 + 反方论证）

  • 已核实：stitcher.io《No more issues》（2026-09-04）确认 Laravel 前一日关闭了部分仓库的 issue 创建。
  • ⚠️ 边界修正（周刊表述偏宽）：该改动只涉及 Socialite、Scout 等 Laravel 包，主框架仓库的 issue 仍然开放（Taylor Otwell 称框架仓库暂不关闭，但未来不明）。周刊开头直接写"Laravel 宣布禁止提交 issue"，实际范围比这窄，引用时需注明。
  • 反方论证（同文作者 stitcher.io，本身也是开源维护者）：
    • 这主要利于维护者，不一定利于用户；
    • PR spam：一次 bug 发版后可能涌来几十个重复 PR —— 与重复 issue 数量相近，但每个 PR 都会触发 CI，自动化开销被放大（可用 GitHub Actions 配置缓解，所以不致命）；
    • AI 生成的 PR 反而更耗 review："我的经验是，AI 生成的 PR 相比作者自己想清方案再提交的 PR，需要更多审查精力"——而"先写 issue"恰好促使提交者先自己思考；
    • 提高门槛与开源包容性相悖：不用 AI 的人（受经济或伦理所限）提交 PR 的投入过高；新手被排除在外——"我们很多人就是从 Laravel、从完全的小白开始的"；
    • 微妙之处：Laravel 已不完全是"开源公司"，它在向开源起家的生态卖产品与服务。

我的评注

这条新闻的内核不是"issue vs PR"，而是：AI 把"提交贡献"的边际成本打到接近零之后，维护者的注意力成了唯一稀缺品。用 PR 替代 issue 是一次过滤器重排——把审查成本从维护者前置给提交者。但它自带一个自我否定的悖论：既然 AI 让 PR 也一样廉价（理由 3 本身就在说这个），那这道过滤器很快会在新位置再次被淹没。更长期的正解不是"关掉某个入口"，而是给贡献渠道加可验证的门槛（可复现的最小样例、CI 闸门、形式化证据）——这直接把话题交给本期第二篇主文：当"产出"泛滥，验证成为新的瓶颈，也成为新的价值锚。

→ 库内呼应：gear-shaft-org-reinvention.md（别外挂，要推倒重来）、echo-gap-memory-reward-inflation.md（信号膨胀）

2. 史上最长的数学程序 ​

原文主张（阮一峰）

  • 费马大定理：大于 2 的整数不满足 an+bn=cn。1995 年怀尔斯（Andrew Wiles）证明，共 129 页，专业数学家也要读几个月。
  • 数学界一直想把该证明翻译成机器可验证程序（Lean），工作量超大，迟迟未完成。
  • 上周一研究团队宣布：Claude AI 用 11 天完成，把怀尔斯证明翻译成 Lean 程序。Lean 是微软研究院 2013 年提出的定理证明语言。
  • 过程中先证了 3 万多个辅助定理（用上 2 万 9 千多个），消耗数十亿 Token，最终代码 1300 万行，"有史以来最长的数学程序"，代码已公布在 GitHub。
  • 意义：大量数学证明难以验证、甚至无人能读懂，现在事实表明 AI 可以用来验证证明是否正确。
  • 附怀尔斯专访片段：苦研八年，醒来睡前都在想，结束后"确实有些伤感，但同时有巨大的成就感，还感到终于自由了……内心终于平静"。

外部核实（把转述钉成事实）

来源：Anthropic 官方《Formalizing Fermat's Last Theorem》（2026-09-04）+ GitHub API。

周刊表述核实更精确的数字
11 天完成✅原文："worked largely autonomously over 11 days"；Claude 日志显示根定理于 Aug-18 02:00:57Z 判为 PROVED
3 万多个辅助定理，用了 2 万 9 千多✅30,300 个定理，最终证明用到 29,500 个
消耗数十亿 Token✅约 60 亿 output token（用能力约当 Claude Fable 5.1 的内部通用研究模型）
1300 万行 Lean✅是社区数学库 Mathlib 的 5 倍以上
代码已公布在 GitHub✅实测（2026-09-16）：anthropics/fermats-last-theorem，Apache-2.0、主语言 Lean、创建 2026-09-04、1,180 star / 102 fork、仓库约 227 MB
（周刊未提）证明的强度—只用 Lean 的 3 个标准公理；comparator 确认定理陈述与 Mathlib 自己的 FLT 陈述一致；Buzzard："除数学公理外无任何额外假设"
（周刊未提）人的参与程度—人类输入仅限少量高层指令（"Jacobian as a scheme 听起来优先级高""尽快推进 Mazur 定理"）

周刊没讲、但最关键的一段（增量）

Anthropic 文中坦承早期多智能体协作失败：agent 们"很快跟丢项目状态、停止有效协作"，这些失败尝试约占最终非样板代码的 7%。转折点是换用协作平台 Prove2Me（哥大 Tianyi Peng 团队开发），它做三件事：

  1. 维护一张定理陈述的 DAG（有向无环图），agent 据此判断下一步该证什么 —— 原文明确点出这是"mitigating memory degradation"（缓解记忆退化）的主要手段；
  2. 把定理陈述与证明拆入不同文件、链接独立维护，加快 Lean 编译、降低资源消耗；
  3. 为每条定理维护自然语言描述以便检索复用，得到更短的证明路径。

另有小实验：三个个人版 Claude Max 订阅，全程只靠 Prove2Me 协作，3 天形式化了维诺格拉多夫三素数定理。

为何重要（不夸大、不打折）

  • 这是**验证（verification）的胜利，不是发现（discovery）**的胜利：证明思路仍走怀尔斯路线（及 Darmon–Diamond–Taylor 的简化版），Claude 干的是"把 129 页人类散文改写成每一步都不许跳的 Lean 代码"。Buzzard 的分寸值得学：这"证明了 FLT，且除数学公理外无任何额外假设"，并且"AI 自动形式化的产物已经健壮到可以被继续搭建"。
  • 结构性意义：当 AI 生成的数学（以及代码、文档）产量爆炸，评审与验证成为唯一瓶颈，形式化等于把评审成本一次性工程化。Anthropic 的预测很实在——以后"面向人类的论文"应配一份形式化证明；不是取代人类可读的阐述，而是人类评审团跟上 AI 产出速度的唯一可行方式。
  • 反向提醒：本期言论里陶哲轩的警告正好构成对偶面（见第七节）。

我的评注

两篇主文合看，本期其实只有一条主线：AI 把"产出"变成廉价品，于是瓶颈与价值整体迁移到"验证"与"注意力"两端。第一篇讲注意力（维护者被 issue 淹没 → 用 PR 筛），第二篇讲验证（人类读不懂 129 页 → 用 Lean 机器核）。同一种压力的两副面孔。

→ 库内呼应：llm-reasoning-verification-thermodynamic.md（可审计验证 Theoria）、cognitive-atrophy-knowledge.md（审查悖论）、echo-gap-memory-reward-inflation.md（多 agent 记忆退化 —— Prove2Me 的定理 DAG 正是对它的工程解）

二、科技动态（3 条） ​

  1. 特斯拉出售 Cybercab —— 特斯拉在美国推出 Cybercab 出租车，并宣布这些车对外出售：买它不是为了自己乘坐，而是投资，每次载客收入与特斯拉对半分；车 24 小时运营，"你睡觉时它在为你挣钱"。但车主承担折旧贬值，还需另购 15,000 美元自动驾驶功能包。阮一峰的洞察：特斯拉卖车后不再持有车辆硬件，仍运营你的车、分走一半收入，从重资产公司变成轻资产公司——"在你睡觉的时候，你的车还能帮它挣钱"。评注：把资本开支与折旧风险转移给散户，本质是车队金融化；"全天运营的车能撑几年"是这笔账的死穴。
  2. 戴森电动牙刷 CameraJet —— 刷头带摄像头 + 照明灯，可用手机查看口腔情况；更关键的是按摄像头拍到的景象自动判断往哪里喷水、加大清洁力度。阮一峰调侃："都已经做到这个程度，不如做个自动刷牙器，张嘴就自动刷完。"
  3. 哈佛 AI 手杖 —— 面向盲人/视障：手机用摄像头、GPS、运动与方向传感器取实时数据，结合导航软件算出下一步方向传给手杖；手杖用哔声提示前/左/右，走错发警报。阮一峰指出尴尬处：需手机全程开启且摄像头要能拍到街面，"还不如把手机功能集成进手杖"。

附：HuggingFace《State of Open Models: Summer 2026》要点（已抓原文） ​

  • 盘子：公开模型仓库 243 万 → 296 万，数据集 71.1 万 → 100 万，Spaces 100 万 → 144 万。分布极端——约 85.6% 的模型历史下载不足 200 次，1.5% 的仓库吃掉 99.2% 的下载。
  • 1. 前沿在加速，且中国实验室跳级：2026 年多个中国实验室跳过了"先小后大"的常规路径；几乎每个月中国最强的开源模型都大于美国当月发布的最大模型。中国月度高线在 754B ~ 2.78 万亿参数之间；美国 7 个月里有 5 个月低于 130B（例外：NVIDIA Nemotron 3 Ultra 561B、Thinking Machines 的 Inkling 952B——后者基于中国模型/工件构建）。
    • 两种策略：Moonshot / MiniMax / 小米 / Z.ai 几乎不发 70B 以下的模型（"前沿专用组合"，赌基准位次与 API 需求）；腾讯与阿里 Qwen 覆盖从 1B 以下到前沿的全谱系（赌"开发者把它当标准家族的基座"）。
    • 美国没缺席，但角色不同：今年发布新开源模型最多的两个组织是 AMD 和 NVIDIA，各 200+ 个仓库——硬件厂把开源模型当"卖芯片的证据"（针对自家硬件优化的模型免费放出，是硬件能跑通的最清楚证明）；中国这边反向发生：开源模型越来越为国产芯片优化。
  • 2. 关注度 ≠ 采用度：今年下载 Top25 与点赞 Top25 只有一个仓库同时出现；2026 年发布的模型没有一个进入下载 Top25，25 个里有 13 个是 2022 年的。all-MiniLM-L6-v2 七个月被拉 15.5 亿次却只有 5,156 个赞。点赞记录"什么让人兴奋"，下载记录"什么真正在被依赖"——把两者互为代理是报道 Hub 时最常见的错误。
  • 4. Qwen 成了社区基座：Moonshot 的前沿专用组合全年 3,700 万次下载，Qwen 全谱系约 20.45 亿次（约 55 倍）。
  • 5. 小模型仍是实用层。
  • 6. 智能体成了新用户（7 月上线的 agent 用量数据集首次量化）：7 月 Claude Code 占 44.4%，但它在 4 月占 67.8%、5 月 64%；Codex 从 10.4% 稳步爬到 20.8%——"这是一个没有在位者的市场，一次发布或一个默认值的改变就能在一个月里移动一半流量"。另一发现是"未登记行"：近 1/4 的 agent 流量来自数据集尚未命名的 harness（5 月时这个比例是 59.8%），4~7 月冒出十几个新客户端标识——"新进者比任何登记表命名它们的速度都快，这本身就是结论"。
    • 配套建设：3 月起论文提供机器可读 Markdown；4 月 agent trace 成为一等数据集类型、每个 Gradio Space 提供 agents.md；7 月 MCP server 推出 hf_fs（千余 token 暴露仓库/存储/文档/论文）；MCP 归入 Linux Foundation 的 Agentic AI Foundation。

六、图片与文摘 ​

  • 图片：美国公路的奇特建筑 —— 美国是"汽车轮子上的国家"，常有人在公路边修造型奇特的房子吸引过路旅客；美国国会图书馆有含 11,710 张此类彩色照片的照片集（Public Domain Review 选登）。
  • 文摘：构建任何东西之前，先问自己三个问题（Jordan Lord《3 constraints before I build anything》，2026-04-07，已核实原文）：
    1. 能不能把产品介绍写成一页纸概要？ 超过一页说明太复杂，不要开发。一页纸是北极星，复用于对投资人、贡献者、团队、家人的沟通；"如果一件事不在那一页纸上，要么不值得争，要么该改那一页纸"。
    2. 核心技术能不能与产品分离？ 产品会不断改方向，核心技术始终如一并持续发展。分离迫使你跳出产品局限思考：手机的核心技术是移动通信，某款手机会失败，移动通信不会。
    3. 产品有没有一个核心特色？ 特色清晰明了、赋予产品独特个性（Minecraft=全部由方块构成；宜家=平板包装自行组装），它缩小决策空间；没有特色或特色选错，就会做出想面面俱到的臃肿产品。
    • 评注：作者是 10 年产品人，"过于复杂 / 没有身份"正是他两个失败模式。与库内 gear-shaft-org-reinvention.md 的"别外挂、要重构"同族：约束不是限制，是把搜索空间压小的工具。
