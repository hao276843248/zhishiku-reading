一、本期主文 ​

1. Jev 决策模型有什么用 ​

原文主张（阮一峰）

  • 上个月最大的 AI 新闻不是 GPT / Claude 的新版本，而是一家名不见经传的公司 TypeSafe AI 发布的新类型模型 Jev，叫"决策模型"。
  • Jev 的最大特点：其他模型返回文字，它返回一个浮点数，表示概率。
    • 是非题：问世上一句陈述"是否正确"，返回 0~1 的置信度。
    • 选择题：给 ABCD 四个选项，返回每个选项正确的概率分布。
    • 评分题（score）：给一组评分标准 + 一篇原始材料，返回一个分数。
  • 周刊给两个真实例子（都是基于 Jev 的浏览器插件）：
    1. 《我用 Ctrl + F 寻找答案》：把 Ctrl+F 从"找词"改造成"找答案"——依次拿每个段落问 Jev"本段是否与搜索词相关？"，相关度最高的段落即语义查找结果。
    2. 《我用 Jev 为网页打分》：给 Jev 一组从低到高的评分标准，让它自动给新打开的网页打分，从而不读网页就知道内容质量。
  • 周刊的核心判断句："一旦 AI 模型返回量化的结果，许多以前无法数字化处理的问题，顿时都能用计算机处理了。"
  • 周刊引 Simon Willison 的评价（一针见血）："Jev 实际上代表着机器学习系统的倒退，走向黑箱系统…… Jev 甚至连'解释'都不给你：你只会得到一个浮点数，这个数字是怎么来的，不知道。"并担忧有人用 Jev 给求职者排名。

外部核实（把转述钉成事实）

我把一手原文都抓下来了，周刊的转述总体准确，以下是更精的版本：

项目核实结果
发布方 / 时间 / 作者✅ TypeSafe AI，2026-09-15 博客《Introducing System One Models & Jev》，作者是 创始人 Diogo Almeida（自称在 OpenAI 参与过让语言模型"听懂指令、能对话"的方法研究，"那项工作后来成了 ChatGPT 背后的研究"），潜伏两年后发布
定位✅ "System One Model"，选输出是 typed probabilistic decisions（带类型的概率决策）；官方原话是 "frontier-intelligence function call: unstructured state in, typed probabilistic decisions out"——把 Jev 类比成一次"前沿智能的函数调用"
三种问法✅ 是非题（官方叫 Noul，CEO 在 Hacker News 确认是 Bernoulli 分布的缩写，非"no/yes"）、选择题（返回置信度 + 全选项概率分布）、评分题；一个 state 可同时塞多个问题、并行求值
性能 / 训练✅ 官方称"System One 任务上智力接近现有 LLM，但快两个数量级、更省"；放弃字符串生成 → 不能幻觉；训练法是自创的 RLCD（Reinforcement Learning for Calibrated Decisions），区别于 RLHF / RLVR
价格✅（Simon Willison 核实）只按输入计费、输出免费，首模型 $0.042 / 百万 token，比 OpenAI GPT-5 Nano（$0.05/M）还便宜
Willison 的批评✅ 确有原文，周刊翻译准确。英文原句 "…represents a regression even further towards black box machine learning systems… the only thing you're going to get back is a floating point number. If Jev marks something as spam, which content signals tipped it off?" 他还做了一个实验：让 Jev 给湾区各城市打"Good city?"的分，Cupertino 最高、East Palo Alto 最低——他注："Huh."（这个排名本身就暴露了隐藏偏见）
第二例文章⚠️ towardai（Medium）被 Cloudflare 拦截（HTTP 403），未能直接核实；第一例（Tymscar《Ctrl+F Finds Words…》2026-09-30，作者 Oscar Molnar，工具名 Hunch）✅ 已核实

Willison 文中还有周刊没提、但很值钱的补充：

  • Jev 的"锯齿"（jaggedness）：目前不擅长数字、日期和"对抗性内容"（官方文档自承）。
  • 最好的用法是凡能表达成分类任务的场景：垃圾邮件识别、打标签、排序、优先级；他自己在试搜索重排（reranking）——先用 BM25 等便宜算法取 100 个候选，再让 Jev 逐个打相关性分。
  • 生态在一周内爆发：开源权重复刻 Kev（基于 Qwen 3.5 出 0.8B / 4B / 9B）、JevBench 基准、llm-typesafe 插件，以及一堆玩梗项目（用 Jev 实现 left-pad、下 2048、甚至当"糟糕的聊天模型"）。

我的评注

  1. Jev 的本质是"把开放式生成压成一次分类/打分"——即表征降维。它没有发明新智能，而是把 LLM 塞回传统机器学习的接口：unstructured in → typed out。妙就妙在，一旦输出是浮点数，一切下游软件不需要"解析自然语言"就能消费它，于是"以前无法数字化的判断"被拉进了可编程世界。这不是智能的进步，是接口的退让——用可解释性换可组合性。
  2. 它与本知识库自己的方法论直接撞车又互补。库内 brain-self-evolution.md（replay_eval）做的就是"用冻结历史给策略打浮点分"，而它暴露的最大 bug 恰恰是：一个浮点数掩盖了判断依据——打分器分不清"助手凑数"和"助手实质"。Jev 把这件事产品化了：便宜到能跑成千上万次实验，但你永远不知道那个 0.87 是怎么来的。Willison 的城市打分实验（Cupertino top / East Palo Alto bottom）就是活证据：偏见不会报错，它只会以一个漂亮的浮点数出现。
  3. 对用户的直接价值：外脑的 semantic_search.py / query_brain.py 目前是关键词/语义匹配，Jev 式的"BM25 粗召回 + 决策模型精重排"正是现成的升级路径——把"这条记忆与查询相关吗"变成一个可批量、可缓存的浮点分。但记住 Willison 的警告：凡涉及给人/给内容排名，浮点数会把偏见藏起来，这类裁定必须留人的眼睛复核（和 replay_eval 的教训同一条）。

2. Markdown 正在变成源码 ​

原文主张（阮一峰）

  • Markdown 以前只用于写文档；htmx 的作者提出一个大胆命题：Markdown 正在变成源码。
  • 三条理由：（1）纯文本，diff / 搜索 / 审查都容易；（2）AI 像母语一样读写 Markdown；（3）人类无需工具即可读写。
  • 推论：既然代码是 AI 根据 Markdown 提示词生成的，Markdown 提示词就该和生成的源码一起提交到 /src 目录。
  • 事实佐证：Markdown 已经以 AGENTS.md 的形式成了源码的一部分。"以后我们必须习惯，Markdown 文档也是源码。"

外部核实

原文是 Carson Gross（htmx 作者、蒙大拿州立大学教授）2026-09-21 的随笔《Markdown in /src》（htmx.org/essays）。比周刊转述更细：

  • TLDR（原文）："Markdown is becoming source code, not documentation；它应被 checkin 到 /src，挨着它生成的代码；代码与测试应从 Markdown 派生，而非从"一次性的提示词"派生。"
  • 核心论证：LLM 常被类比为"编译器"（把高层规格编译成低层实现）——但编译器工作流保留源码，而当下 LLM 工作流不保留：代码是由一串临时 prompt 喂给 agent 生成的，结果代码本身成了唯一的"ground truth"，而意图散落在 Linear / Slack / wiki 里。Gross 主张：把 Markdown 提升到 /src/md，记录架构决策 / 源码级决策 / 低层数据设计决策——比传统设计文档低一层、更接近"规格（spec-ish）"。
  • "局部性（locality）"是主论点：Markdown 放进 /src，好处是模块自带解释其意图的 Markdown，没有"远处的规格（specification at a distance）"，人和 agent 都不必再去别处找上下文。
  • 对"测试即规格"的回应：Gross 认为测试不是好的人机交互媒介（太多仪式感、层次太低、放不进 Mermaid 图），于是提出分工——Markdown 在 /src 当（准）规格，测试在 /test 基于 Markdown 提供自动正确性确认。
  • 他引用了 Hartley Brody《Markdown is the new source code》作为先声。

我的评注

  • 这条直接给本知识库外脑的存在合理性盖章：外脑存的 Markdown，本质就是"意图的源码"——它记录的不是"结论是什么"，而是"为什么这么判断"。AGENTS.md、HEARTBEAT.md、各 topics/*/index.md 全是同一个范式。
  • 但要提防一个反噬：源码必须真的是 ground truth，不能是事后补写的文档。一旦 Markdown 变成"代码写完后补的说明"，它就退化成传统文档，diff 出来的只是噪声。所以这条路成立的前提是先写 Markdown（规格），再从中派生代码/测试——顺序反了就没意义。这与 #413 的"代码即债务""糊状千层面（分层＝可替换）"是同一枚硬币：规范层的价值，取决于它是否真的在被消费。
  • 与库内 llm-wiki-gbrain-knowledge-paradigm.md（Karpathy 式 Compiled Truth + Timeline）严丝合缝：Compiled Truth 就是"源码"，Timeline 就是"提交历史"——Markdown-as-source 是这套架构的工程化身。

3. 不能摄像的摄像头（苹果） ​

据 theapplepost 报道，苹果将发布一款智能家居摄像头，最奇特处：它是摄像头但不录视频。完全靠 AI 分析环境、报告检测到的内容（如"有陌生人敲门"），只给详细文字描述而非视频。周刊的疑问：文字方便处理，但入室盗窃、包裹被盗等场景确实需要视频证据，苹果怎么处理？

  • 我的评注：这是"AI 把连续信号压成摘要"的又一个样本——和主文一的 Jev、和 #413 的"魔法师时代"是同一个结构问题：连续、可回看的原始信号（视频/像素）被替换成离散、方便消费的摘要（文字/浮点数），代价是原始证据被丢弃 → 事后验证不可能。摄像头不录像的那一刻，它就不再是"记录设备"，而是一个"在替你下判断的黑箱"。当判断出错（把快递员判成入侵者、或漏判），你连回看的素材都没有。
  • 关联 cognitive-atrophy-knowledge.md（System 0 / 判断外包）、llm-reasoning-verification-thermodynamic.md（可审计验证）。

4. RSA 因素分解的新纪录 ​

  • 周刊：RSA 破解难度＝公钥能否被因数分解；密钥位越多越难破，此前最高纪录 768 位。2026 年 9 月，Anthropic 一位软件工程师借助 Claude，破解了 896 位 RSA 密钥，并公布密钥与两个质因子。据其透露：用 Claude 把质因数分解库 CADO-NFS 移植到 GPU，在 2048 个 GPU 上跑了 10 天得到结果。启示："一个个人就能调用资源破解这么长的密钥，大机构能破解多少位？"结论：RSA 密钥最少要 2048 位。
  • 外部核实：原文是 Stephen A. Weis 的《RSA-896》（saweis.net，2026-09）。关键细节比周刊更准，且周刊有一处需要修正：
    • ✅ Weis 自述：是他在 Anthropic 的集群上完成的——"orchestrated running on a fleet of up to 2048 GPUs as a low-priority job during unused idle time"，10 天约合 30 GPU-年的算力。
    • ⚠️ 周刊"一个个人就能调用资源"的叙事要打折：他调用的不是个人算力，而是大机构（Anthropic）闲置时的数据中心级 GPU 集群。真实图景不是"个人变强了"，而是"大机构的闲置算力 + LLM 降低工程门槛"两者叠加。
    • ✅ Weis 明确：这次没有实质改进 GNFS 算法本身，也不影响已部署的 RSA-2048 的安全性；但它证明 RSA-1024 对拥有数据中心级 GPU 的行为者已不安全。
    • ✅ 周刊"此前纪录 768 位"属实（RSA-768 是 2009 年著名结果）；位数从 768→896 成立。
  • 我的评注：这条的启示不是"加密被破了"，而是 LLM 作为"工程杠杆"：把"把一套科学计算库从 CPU 移植到 GPU"这种苦活变得可行，于是门槛从"算法突破"降到"算力 + 一点点工程"。这与 #413 的"AI 最先吃掉翻译层"同源——LLM 最擅长的正是这种跨平台的机械移植（CADO-NFS → GPU）。对用户的直接含义：任何自建服务的密钥长度、哈希参数，都该按"对手有数据中心 GPU"来设下限，而不是按"个人算力"。
  • 关联 topics/cybersecurity/、llm-reasoning-verification-thermodynamic.md（LLM 辅助科学计算）。

九、一句话判断 ​

本期主线：AI 的下一步不是"更会说话"，而是"把判断变成一个数"——接口退让换来可编程，代价是可解释性被抹平。

  • 主文一（Jev）是接口革命：把开放生成压成一次分类/打分，让"以前无法数字化的判断"进入可编程世界；但 Willison 的批评点破了代价——浮点数不会报错，它只会把偏见藏得好好的（他的城市打分实验就是活证据）。这与本库 replay_eval 的教训同构：一个分数掩盖了它该被追问的依据。
  • 主文二（Markdown in /src）是接口革命的对偶：Jev 把输出变成数，Gross 把输入变成可 diff 的源码——两端都在把"模糊的意图/判断"逼成"可版本化、可审查的文本"。 这直接是本知识库外脑的立身之本。
  • 两条简讯（不能摄像的摄像头 / RSA-896）是同一句话的两面：前者：丢了原始信号，验证就不可能；后者：原始门槛（工程）被 LLM 打下来，只剩算力。
  • 对你直接有用的三件：skillsgist（私有 Skill 分发思路）、yovoice（把知识转语音）、Video Transcript（视频→字幕→外脑）；自托管线加 open-compute（去 Cloudflare 化，Apache-2.0）。提醒两条：自托管先查许可证（EdgeChat 是 GPL-3.0）、极新项目先借思路别上生产（skillsgist 2 周 / Burrow 10 天）。
  • 最该记的一句是 Rauschmayer 的下线声明：AI 爬虫正在把"免费公开的知识"变成净亏损——这反过来证明外脑的价值：私有的、被人消费的 Markdown，才是 AI 时代不会被吸干的知识形态。
