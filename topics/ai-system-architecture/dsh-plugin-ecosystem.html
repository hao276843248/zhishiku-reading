六、可复用教训（元） ​

  1. 先分清"宿主"和"被转述的品牌词"。"在 X 里装了个插件"——要问：X 是宿主工具，还是只是视频借用的名头？本次真身是网页玩具，DSH 集成全在二创里。
  2. "用 coding agent 来了解项目"正在变成 README 惯例。这既方便（AI 能读架构细节），也是信任转移：内容不再由人直接审阅，读者被引导把理解权交给模型。本项目与 cleanyourtv 同款——两次出现，值得记为一个模式。
  3. 梗类项目的许可陷阱：代码 MIT ≠ 素材可用。人像/视频帧通常被单独排除。
  4. 星数 + watch + 最后推送是最便宜的真伪筛子：★328 / watch 0 / 2 个月未更新 = 个人玩具级，不是基础设施；与官方 ★254,706 差 3 个数量级。上次（tv-vibehack ★26 vs cleanyourtv ★4,310）是同一把尺子的另一次使用。

七、"Token 自由"：dsh-workbuddy-connect 实测（2026-10-20） ​

视频说法：开源插件 dsh-workbuddy-connect 让 DSH 用户无需 API Key、无需独立网关，只要本地登录 WorkBuddy 账号，就能直接使用 DeepSeek Flash、Step-5 等模型；插件自动读取本地客户端登录态与模型目录，支持国内版/国际版双账号。

7.4 📌 惯例第 3 次出现：README 首推"把安装交给 Agent" ​

README「安装」章的第一推荐不是命令，而是把一段提示词原样发给本机已有的 Agent（DSH Agent / Codex / Claude Code / Cursor 都行）：

"请帮我安装并验证 DSH 插件 dsh-workbuddy-connect…先阅读项目 README，确认我实际使用的界面与 DSH 内核版本…任何本地文件或配置改动，先征得我同意并做好备份…若 Desktop 安装仍因 generation 校验失败…请如实报告…不要修改依赖包或绕过校验。"

→ 与 cleanyourtv 的 PROMPT.md、滑杆项目 README 同款手法，这是第 3 例（本文件第二节已记为模式）。 → 但这次的提示词明显更克制：明确要求先备份、先要许可、不绕过校验、失败如实报告 —— 是"把操作外包"与"保留人审"之间较好的一个折中。

7.5 ⚠️ 风险面（这条最该说的） ​

  1. 它必须持有你的令牌才能工作 —— README 自己列出「令牌有效期」显示与 logout（清理凭据）子命令，凭据落在 workbuddy.json。读你登录态的插件天然在信任边界之内；这不是 bug，是设计。装之前该问：owner 是谁？凭据存在哪个文件？怎么撤销？
  2. "免费"的真相是别人的订阅额度 —— 积分不自动轮询，原因写得很直白：「每次读取都是真实计费查询」；推理档位检测「会消耗积分」。不是无限免费，是把 WorkBuddy 的付费额度转接到 DSH。
  3. 促销窗口随时关 —— 限时免费、夜间折扣 徽章由服务端下发，「过期后徽章自动撤销」；README 甚至记了一个细节：服务端把折后价直接写进倍率字段，原价无法还原 → 定价权 100% 在厂商手里。
  4. 企业账号要特别小心 —— 国内版企业账号（enterpriseId 非空）走企业计费接口读周期额度。用公司账号接出来跑私活 = 用公司额度做私事；对有内部 AI 平台的单位，合规上尤其敏感。
  5. 违反 ToS 的可能性高 —— 把订阅客户端额度转接到第三方客户端，几乎必然与厂商协议冲突。生态里 workbuddy2api-panel（★4,110）公开写"自动完成任务中心全部任务"（= 自动刷积分）、masknull 版带「每日自动签到」→ 这类行为被风控识别即封号。
  6. 同名仓库 = 供应链风险 —— ★3 / ★48 / ★1,463 三个同名或近名仓库行为不同，随手搜一个装可能拿到完全不同的代码。
