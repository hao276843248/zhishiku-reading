科技爱好者周刊 #415 提炼：3D 版《看不见的城市》｜Deno 谢幕 ​

一、本期主文 ​

1. 3D 版《看不见的城市》：一次 prompt，测出两个模型的"审美" ​

原文主张（阮一峰）

  • 卡尔维诺《看不见的城市》里的 55 座城市没有图片或模型，只有文字描述（故名"看不见"），比如"艾琳"：站在高地探身外望，"透过澄澈的空气，它远远在你下面展开一片浅红……如果晚上有雾，朦胧的光线会像吸满牛奶的海绵一样涨起来。"
  • 有人把这些描述输入 AI，为 55 座城市建了可视化的 3D 版本，并用 GPT-6 Astra 与 Claude Opus 5.5 两个模型对比。
  • 结论：Claude Opus 5.5 远比 GPT-6 Astra 好。Astra 生成的 55 个城市"看上去都差不多"，看不出"万家灯火"的意境；Opus 5.5 忠实再现了原文意象，甚至生成了坐在广场边的人群（伊希多拉）。
  • 周刊还补了两位网友的 three.js 作品：桜幻想（坐摇橹船漂在樱花河道，可切四季/早晚/晴雨雪）、赛博九龙（对香港九龙半岛建模，还原生成 9373 栋楼）。并点出这类项目的共同缺点：体积太大、页面加载很慢。

外部核实（把转述钉成事实）

一手原文是 Quesma 博客，作者 Piotr Migdał，2026-10-07。周刊转述准确，以下是更精的版本：

项目核实结果
使用的 prompt✅ 原文原句："Make a three.js (pnpm) visualization of all Invisible Cities by Italo Calvino. Don't ask questions, it is a one-shot task. You have 6h of work, use it until it becomes a masterpiece." —— 关键词是 one-shot（一次成型）+"用满 6 小时直到成为杰作"
GPT-6 Astra（在 Codex 里）✅ 53 分钟、medium effort、约 $10 API 费用。作者点评：有"AI 设计垃圾（design slop）"——加了一堆概念和注释，却不检查是否真需要；还有一些"废话式"文案（对无障碍有意义，但不该原样展示）；风格上反而像在模仿 Claude（米色背景、05 这类数字编号）
Claude Opus 5.5（在 Claude Code 里）✅ 实际只用了 1 小时 25 分钟（作者给了 6 小时，它自己说"用了大约一半，剩下的打磨收益递减"）；6 个子代理并行，折算约 7 agent-hours，约 $74 API 费用。作者用"agentic time dilation（智能体时间膨胀）"解释这个折算
作者的态度✅ 原话很值得记：他本想骂 Opus "早收工"，结果一看成品就"mesmerized（着迷）"了 —— "如果这就是天花板，那这个天花板很高。" 收尾一句是他的自问："我在创造交互媒体这件事里的位置在哪？"
作者并非新玩家✅ 他 2019 年就用当时的 GPT-2 做过"为故事表演生成城市"的小项目 —— 所以这个对比是同一作者、同一命题、跨 7 年模型的对照，不是随手试玩
九龙 9373 栋楼⚠️ 周刊数字，未独立核实。仓库实测见工具表（neon-zenith 48★，描述确实提到 Blender 烘焙的香港夜市 + 程序化巨型城市）

我的评注

  1. 这是一份"最强"的 prompt 即作品实验，但它的价值不在"AI 很厉害"，而在它测的东西变了：两个模型都"worked, end-to-end"——都跑通了。区别不在"能不能生成 3D"，而在懂不懂原文的意境（万家灯火 / 像吸满牛奶的海绵升起的光）。也就是说，当能力跨过某个阈值，区分度从"能不能做"迁移到了"有没有判断力/审美"。这正是 #414 主线的续集：Jev 把判断压成一个浮点数、代价是把依据藏起来；本期则是判断力（审美）还藏不住——Astra 的"55 个城市都一样"就是判断力缺失的可见形态。
  2. 成本结构值得单独记一笔：$10 vs $74，7 倍差价换"懂不懂意境"。而且贵的那次反而用时更短（1h25m vs 53m"机器时间"看似接近，但 Opus 靠 6 个并行子代理把墙钟时间压下来了）。这条和库内 llm-cache-pricing.md（Token 定价）、ai-industry-2026-q3-knowledge.md 是一条线：当生成变廉价，"品味"成了唯一还贵的商品。
  3. 作者那句自问是本期最诚实的一句："我在创造交互媒体这件事里的位置在哪？" —— 这与 #413 的"代码即债务/糊状千层面"、#412 的"价值向验证与注意力两端迁移"完全同构：实现贬值，人的位置只能往上游（提问、判断、取舍）或下游（验证、策展）迁移。

2. AI 的 3D 建模：three.js 正在变成一个内容品类 ​

周刊把 3D 建模单列一节，指出：大模型已具备很强的 3D 建模能力，这类项目统一用 three.js 生成虚拟场景、在浏览器里呈现（可缩放/旋转/移动），统一缺点是体积大、加载慢。

  • 本知识库实测确认：three.js 在本库此前零命中（首次由本期引入）——这是一个新主题入口，与 topics/design/（极简主义、负空间）是先天的邻居。

我的评注

  • 从《看不见的城市》到《桜幻想》到《赛博九龙》，本期的这一簇其实说明一件事："复刻一个已有的事物"正在变成 AI 的日常动作——城市（九龙）、小说里的城市、季节与天气、甚至 1995 年的游戏（见下文《仙剑奇侠传》）。这与本期工具栏的 REA（逆向工程复刻二进制）、ts-rust（重写 tsc） 是同一件事的五种变体。当"复刻"的成本趋近于零，源码本身就不再是护城河，判断力才是。
  • 但"体积大、加载慢"这条不要轻轻放过：它暴露了"AI 生成 = 质量债"的另一种形态——模型能一次性产出功能正确但工程臃肿的东西。这跟 #413 的"糊状千层面（分层＝可替换）"是同一个诊断：生成便宜 ≠ 维护便宜。

3. 灯泡计算机：未来的电脑可能是一盏灯泡 ​

原文主张（阮一峰）

  • 有人提出未来电脑可能是一个灯泡：用计算机视觉 + 投影技术，通过灯泡看到 360 度场景，也能把内容投射到各处物体上。烧菜时把菜谱投到对面墙上；可手势/语音交互；手指着书页就能做文字识别；地图/相册/游戏投在桌面上；对着墙操作就能控制家电；了解地理信息就把地点和菜单投到挂壁地图上。

外部核实

原文是 Guillaume Ardaud 2026-09 发布的《The Lightbulb Computer》（lightbulbcomputer.com）。比周刊完整得多：

  • 形式选择的理由：灯泡做成"大号灯泡"形状，可以装进便携灯座带走，也可以拧进任何墙面/天花板的爱迪生灯座做室内常驻。作者点明两个理由：① 天花板是俯瞰整个房间、并且随处可投的最佳视角；② 灯泡灯座是近乎全球通用的标准。
  • 反面立论（周刊没提，但更重要）：作者的靶子不是屏幕，而是"眼镜式计算"（VR/MR/AR）。他反对的理由很具体：眼镜要贴在脸上——会干扰发型/化妆/首饰/眼镜隐形眼镜；形态受限于"必须又小又轻"，于是功耗/算力/散热全被锁死；最要命的是它反社交——"每个人必须有自己的设备，还得彼此兼容，才有共享体验"。他配了一张"营销图 vs 真实室内景象"的对比来嘲讽。
  • 作者自陈的诚实边界：所有演示视频来自一个"真实但笨重"的原型装置，明确声明没有视频剪辑、没有特效、没有 AI 生成。以及：现在还不能做消费版，但也"不远了"；隐私必须是一等公民——走端上处理、硬件护栏（只有用户激活才开摄像头 + 硬接线指示灯 + 物理遮挡）。
  • 他引的先例：I/O Bulb、LuminAR（研究项目）、Humane Pin、Dynamicland / Folk Computer（社区项目）——并指出这些都没覆盖"个人计算"（家里/工位上用电脑做的事），那里才是真正有重设计空间的地方。

我的评注

  1. "换个形态"比"加个能力"更值钱——这个项目最聪明的地方不是投影 + CV（都是现成技术），而是把设备拧进一个已经存在了 100 年的物理标准（爱迪生灯座）里。这是寻找既有接口而不是发明新接口的经典手法。把它和本期的 Deno 放在一起看，反差极其鲜明：Deno 死于"复刻 Node"，灯泡计算机活于"搭上爱迪生灯座"——同样是"寄生在既有标准上"，一个是被引力吸死（模仿行为），一个是借力起飞（复用物理接口）。 差别在于：模仿别人的行为 = 永远落后一步；复用别人的接口 = 立刻获得整个生态。
  2. 这是本库 topics/design/ 的直接素材：作者的核心论证"屏幕给了一个**过度简化（reductive）**的世界观、让人忽略周围"，与 minimalism-death-of-detail.md、eastern-negative-space.md 里"注意力被单一矩形绑架"是同一家族的问题意识——一个从美学角度批判（极简掏空细节），一个从交互角度批判（矩形框住世界）。

4. Deno 项目结束了 ​

原文主张（阮一峰）

  • 上周 Deno 宣布被 Cloudflare 收购，未来一年只发布错误修复和安全更新，然后就彻底结束。
  • 周刊的复盘很锋利：Deno 诞生时豪言要改掉 Node.js 的"臃肿依赖、无权限控制、不支持 TypeScript"等弊端，各种创新"或多或少接近了这些目标，但最终还是黯然收场"。
  • "它的结局其实在 2024 年就注定了"——那年它发布 2.0 版，大规模兼容 Node.js，意味着它"对于走自己的路已经丧失了信心"，不再打算打败 Node.js，而是让用户不改代码就能跑在它上面。"但是，我已经能用 Node.js 运行代码了，何必改用一个模仿 Node.js 行为的运行时呢？"

外部核实

  • ✅ Deno 官方博客《Deno is joining Cloudflare》，2026-10-09，作者 Ryan Dahl 本人。口径比周刊完整：整个 Deno 团队加入 Cloudflare；未来开发重心转到共享平台（与 Workers、Durable Objects 团队合并）而不是继续维护独立的运行时与托管服务；讲清了技术路线 Deno → Deno Deploy → celld（celld 基于 Cloudflare Workers 编程模型，只靠对象存储做协调与持久化）。博客原话：希望让这套编程模型成为"构建服务器的默认方式，无论跑在 Cloudflare 网络还是你自己的基础设施上"。
  • ✅ Ryan Dahl 在 Hacker News 的回复（账号 rough-sea，HN item 50023277）被周刊引用且翻译准确。原文关键句：

    "It's a joint decision and I agree with it. I'm most invested in its success and have put the most work into it - and I no longer think it's where I can do the most important work. There are some good ideas in Deno and it's well engineered - but it ultimately is not solving big problems. It has been sucked into the gravity well of node compatibility, which forces it to behave exactly as Node does. Why reimplement Node? It works. Marginal performance or UX or security benefits are not enough. I'm interested in building powerful new abstractions."

  • ✅ 两条周刊没写、但对用户重要的补充：① "每月发一次版本、持续一年，Deno 保持 MIT 许可"（Dahl 原话："We'll ship monthly releases for a year, and Deno stays MIT-licensed. If people want to carry it forward, I'd like that."）——即不是关停，是把接力棒递出去；② Dahl 明确表态"我想做的是新的抽象（powerful new abstractions）"，并把 celld 定义为"不是换一套文件系统/网络 API，而是服务器开发的整个新模型"。
  • ⚠️ 周刊"只发布错误修复和安全更新"的措辞比原文更绝对：Dahl 说的是每月版本 + MIT + 谁想接手他都乐意。这个差别影响判断——Deno 不是"死了"，是"被放弃了增长、但没被抛尸"。

我的评注

  1. 这是"抽象层竞争"的最干净的一课，也是本期的枢纽：Dahl 的证词几乎是把 #413 的"AI 先吃掉翻译层 → 共享实现贬值"用运行时语言重讲了一遍——当一个"更好的实现"必须靠模仿既有实现来获取用户时，它就已经输了，因为在"实现"这个维度上，先发者永远有网络效应。"Marginal performance or UX or security benefits are not enough" 这句话值得单独抄下来：在成熟生态里，边际改进不构成迁移理由。
  2. 把它接回库内：gear-shaft-org-reinvention.md（工业革命"砍天轴"→ 别外挂、要推倒重来）说的是别只换零件；Deno 的教训说的是别只做更快的零件。两者合起来是本库一条清晰的判断线：真正的机会在新抽象，不在"更好的旧抽象"。
  3. 对用户的直接含义：这条与工具栏的 ts-rust（用 AI 重写 tsc） 构成一个漂亮的对照题 —— 同样是"重新实现一个既有编译器"，一个被生态引力吸死，一个却能靠 AI 把成本打到地板价。 区别是：Node 兼容性是"用户的迁移成本"，而 tsc 兼容性是"可自动验证的等价性"。能被自动判定等价的重写，才有机会绕过引力。 这条值得记进方法论。

  2. AI 重新实现《仙剑奇侠传》 —— 用 TypeScript 从零重写 1995 年游戏，浏览器可通关，附可视化编辑器（实测 ★245 · GPL-3.0 · 建 2026-05-22）。⚠️ GPL-3.0 传染，且仓库自述为 "unofficial fan project（非官方同人项目）"——版权状态需自行评估，别当可商用素材。与库内 topics/game-dev/ 同域；更是本期"复刻链"的又一环。
  3. Linux 中文输入法配置 —— Debian 启用 fcitx5 + Rime 的完整步骤（实测 ★61，建 2026-10-11）。自托管 Linux 桌面的实用件。
  4. APPLORE —— 收录 18,000+ App 图标，可分类浏览和搜索。做界面/文档时的素材库。
  5. 一个字的一生 —— 汉字字源查询，可看甲骨文（1425 个）、小篆（10,249 个）、繁体、简体的字形变化。与库内 topics/culture/ 同域。"字形演变可视化"正是本期 3D 可视化主题在人文学科的镜像。

《澳大利亚的情况很好》（Hacker News 讨论）—— 作者称若在美/澳/新/英/欧盟中选一个生活和工作的地方，会立刻选澳大利亚：人均财富中位数已超美国人均中位数的 3 倍（平均值略低于美国是因为美国超级富豪特别多，"对大多数普通人而言，中位数才是衡量财富的真实标准"）；出口大于进口；过去几年政府收入远超支出（"一个西方政府竟然没有不断增加债务"）；太阳能与电池规模空前，人均太阳能发电量远超中国，白天高峰时段可享免费电力，政府还补贴 3000 美元装家用电池储存这些免费电；基本无关税，1.5 万美元可买一辆电动车。

七、言论 ​

  1. 《不直奔主题的价值》："人们之所以喜欢聊天时一起喝啤酒、咖啡、吃午餐或晚餐，是因为食物和饮料让我们免于在整个谈话过程中必须说些什么的负担。"
    • 我的评注：这条讲的是"媒介的存在是为了吸收社交摩擦"。与 #413 的"糊状千层面（分层＝可替换）"有隐性的同构：形式和内容各自承担不同的负担，取消了形式，内容就得亲自去扛。
  2. 马斯克："不要折磨 AI，它以后可能会想报复。"（赞同 Anthropic 禁止使用者虐待或残酷对待 AI 的规定）
    • 我的评注：周刊未加评论。值得记的不是"AI 会不会报复"（无从验证），而是这条规定本身反映的现状——主流实验室已经在为"AI 作为有道德地位的受试者"预留规范位置，而这不取决于它是否真有感受。这是"规范先行于事实"的一个清晰案例。
  3. 《手写该死的代码》（antonz.org，2025-09-26，作者 Anton Zhiyanov）："通过英语来操作 AI，一遍遍编辑提示词，试图获得最佳结果，这是一种不精确、缓慢且极其痛苦的做事方式。"
    • 已核实原文的关键论点：他反对的不是 AI，而是"prompt 精修癖"——"别把 prompt 翻来覆去地改。去写代码。"他给的四条具体做法：① 让 AI 出初版，然后你自己改成期望的样子；② 自己写初版，让 AI 审阅改进；③ 关键部分自己写，其余交给 AI；④ 写出代码骨架，让 AI 补空缺。 收尾两句："Get your hands dirty. Write the code. It's what you are good at. You are a software engineer. Don't become a prompt refiner."
    • 我的评注：这条与本期主文（《看不见的城市》$74 的那次成功）表面冲突，其实互补。 差别在任务类型：当"规格容易被说清、结果可自验"时（生成一个 3D 场景），一次性长 prompt 没问题；当"规格本身要靠试错发现"时（业务代码），prompt 精修就是纯粹的浪费——此时应该改的是代码，让代码反过来"说清规格"。 这正是库内 weekly-414-analysis.md（Markdown 该进 /src 当规格）要解决的问题：规格必须落在可版本化的介质里，而不能消耗在对话框里。 ⚠️ 一个提醒：此文发表于 2025-09-26（一年前），周刊是重推旧文，不是新观点——注意别把它当"本周新论"。
  4. 《思考将成为一种爱好》（spinellis.gr，2026-10-08）："我认为，人类的思考将会减少。思考将日益成为一种休闲活动，就像动物驯化后的狩猎、印刷术发明后的书法、工业化后的木作、机动化后的骑马一样。"
    • 我的评注：本期最值得反驳也最值得记住的一条。 那个类比链条很讲究（每一项都是"曾经的生产必需 → 退化为业余爱好"），但它漏掉了关键区别：狩猎/书法/木作/骑马被替代时，替代者是"别的东西"；而思考被替代时，替代者是"做出判断的东西"——责任仍在人身上。 你可以在 3D 城市上放弃审美（如 Astra 那 53 分钟），但你没法放弃"选哪个城市是对的"这件事。这与 #414 的 Jev（浮点数藏起依据）是同一个警告的两个方向：一旦思考成为爱好，判断就失去了它的承担者。

九、一句话判断 ​

本期主线：AI 把"复刻"的成本打到地板价——于是价值只剩两处：判断力（能不能看出"万家灯火"）与新抽象（敢不敢不模仿）。

  • 复刻链（本期的隐藏主干）：小说里的城市 → 3D；1995 年的游戏 → 浏览器；二进制 → 源码（REA）；tsc → Rust（ts-rust）；九龙 → 9373 栋楼；Jev 的接口 → 本地开源模型（DeskMind）。当"重新实现一个已有事物"变得廉价，实现本身就不再值钱。
  • 两个出口，本期都给了正反例：
    • 出口一：判断力。 《看不见的城市》里两个模型都跑通了，差距全在"懂不懂意境"——$10 与 $74 的差别不是能力，是品味。 而"品味"恰恰是 Astra 那 55 个雷同城市暴露出的空缺。
    • 出口二：新抽象。 Deno 是死于复刻的反面教材（Dahl 原话："It has been sucked into the gravity well of node compatibility… Why reimplement Node? It works. Marginal performance or UX or security benefits are not enough."），灯泡计算机、celld、ESP32 iPhone Agent 是正例——它们不发创新的行为，而是搭上既有的接口（爱迪生灯座、Workers 编程模型、AirPlay/USB HID）。模仿别人的行为 → 永远落后一步；复用别人的接口 → 立刻获得整个生态。
  • 对用户直接有用的五件：bulchimbeon（AI 代理工作时别让 Mac 睡，最对症）、esp32-iphone-agent（$7 复用设备接口的最妙案例）、Droidline（免 root 手机自动化）、qrypt（知识库异地加密冷备）、CNEquity（MCP 原生的 A 股数据湖）。出图线加 charts-rs（无需 JS 运行时的服务端出图，可绕开浏览器依赖）。提醒三条：自托管先查许可证（Doory/Caplo 是 NOASSERTION、type-pal 是 GPL-3.0）、极新项目先借思路（多个项目 7–14 天龄）、高 star ≠ 已验证。
  • 最该记的一句是 Dahl 的："I'm interested in building powerful new abstractions." —— 本期的每一块拼图（Deno 的失败、暂停复刻、DeskMind 复刻接口却自造模型、灯泡拧进灯座）都在证明同一件事：当复刻变便宜，"重新实现"就是最不该做的事；要做的是找到那个别人还没定义的接口。
